# ADM-022 — area facts for saved places and plans

Refs #569. OpenAPI 1.0.0-alpha.33, stacked on GoGo-BE#583 (ADM-021, alpha.32). No migration. Consumer: GoGo-MobileApp#214 (ADM-205).

## Behaviour

`GET /v1/me/saved` still returns the whole list, newest first, and every item now carries `area` (`SavedItemArea`):

| Item                                                                               | `scope`                                               |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Place with a `VERIFIED` mapping in the published dataset                           | `commune`, with province and commune codes and labels |
| Place without one (auto-matched, under review, rejected, stale, unmapped, missing) | `unknown`                                             |
| Plan whose stops are all in one commune                                            | `commune`                                             |
| Plan whose stops are all in one province, across communes                          | `province`                                            |
| Plan whose stops span provinces                                                    | `multiple_provinces`                                  |
| Plan with any stop lacking such a mapping, no stops, or not found                  | `unknown`                                             |

A plan is never placed by its first stop, and a plan is not assigned to the area of the stops that happen to be mapped. Labels come from the published dataset; a code it does not carry, or a commune under another province, is `unknown`. With no published dataset every item is `unknown` rather than the request failing. The whole list costs at most five queries, however many items it holds (saved rows, published dataset, plan stops, place mappings, unit labels); an empty list or no published dataset stops earlier.

`GET /administrative/locate` takes the device position in its query string. Keeping those coordinates out of request logs and Sentry events is GoGo-BE#591 (SEC-588), which must merge before this change. Grouping and ordering are the client's, over the full list.

`GET /v1/administrative/locate?lat&lng` answers which current commune or province contains a position, against the boundary release bound to the published dataset: one containing commune that agrees with its unit's province is `commune`; a point claimed by one province only (including a shared commune edge inside it) is `province`; anything else is `unknown`. It reuses the resolver's containment query, stores nothing, and answers `Cache-Control: private, no-store`. 503 when no dataset is published.

## Rollback

Revert the application; nothing is persisted. Older clients ignore `area`. The locate endpoint is additive.
