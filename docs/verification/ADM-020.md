# ADM-020 — room administrative area

Refs #567. OpenAPI 1.0.0-alpha.32. Migration 0063. Consumer: GoGo-MobileApp#207 (ADM-202).

## Behaviour

A room constraint can carry a canonical area: a province with an optional commune (a null commune is the whole province), the same shape and validator as the account area (ADM-019). The server validates the codes against the published dataset inside the write transaction and stores the codes, the dataset version and the labels it resolved. Clients never supply labels; `provinceName`, `communeName` and `status` sent back from a read are ignored.

Write semantics:

| Request                                 | Create   | Constraint update                                                              |
| --------------------------------------- | -------- | ------------------------------------------------------------------------------ |
| omitted                                 | no area  | keep the stored area                                                           |
| `null`                                  | no area  | clear                                                                          |
| same dataset/province/commune as stored | —        | keep the stored snapshot unchanged, even if its dataset is no longer published |
| any other value                         | validate | validate against the published dataset                                         |

Invalid codes or a commune outside its province are 400; a dataset that is not the published one is 409 `ADMINISTRATIVE_VERSION_CHANGED`. Setting an area clears the legacy `areaKey`; nothing is mapped from `areaKey`, and existing rooms keep it with a null area. Origin coordinates and radius stay independent: no position is inferred from an area. Host, editable-state and `expectedConstraintVersion` checks are re-evaluated under the room row lock, and every accepted write marks earlier scores and plans stale (FR-ROOM-005).

`RoomSummary.constraints` now has its own response schema (`RoomConstraints`) carrying the stored labels and `status`: `needs_reselection` when the stored dataset is not the published one.

Candidate retrieval treats the area as a hard scope alongside origin/radius: a place qualifies only with a `VERIFIED` mapping in the same dataset version and matching province (and commune when set). Auto-matched, under-review, rejected, stale and unmapped places are outside every area, the same bar publication applies. A room whose area belongs to an unpublished dataset is refused with 409 `ADMINISTRATIVE_VERSION_CHANGED` by generation (before a run is recorded), finalize and regenerate; the CMS ranking replay records it as a skipped run.

Not run: DEV deploy and migration on DEV, device acceptance, the full unrelated integration suite.

## Rollback

Revert the application first; migration 0063 is additive (nullable jsonb plus a CHECK) and older code never reads the column, so it can stay. Dropping the column is for an isolated rehearsal only — it erases saved room areas.
