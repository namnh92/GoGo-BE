# ADM-021 — discovery scoped by position or canonical area

Refs #568. OpenAPI 1.0.0-alpha.32. No migration. Consumer: GoGo-MobileApp#209 (ADM-204).

## Behaviour

`GET /v1/places/search` accepts an optional canonical area next to the existing position parameters:

- `datasetVersion` + `provinceCode` (both required together), optional `communeCode` under that province. Omitting the commune scopes to the whole province.
- A position (`lat`/`lng`, `radiusM` defaulting to 10 km) **wins** when both are sent. The two are never intersected, so an unrelated account area cannot empty a position-scoped page.
- An area matches only places with a `VERIFIED` mapping from the same dataset version and matching codes — the bar publication uses. Auto-matched, under-review, rejected, stale and unmapped places are outside every area.
- `meta.location` reports what actually scoped the results: `{ source: 'gps' }`, `{ source: 'administrative_area', area: { datasetVersion, provinceCode, provinceName, communeCode, communeName } }` with server labels, or `{ source: 'none' }`.
- A code that is not current or not under its province is 400; a dataset that is not the published one is 409 `ADMINISTRATIVE_VERSION_CHANGED`; a partial area (province without dataset, commune without province) is 400.
- Every other filter, ranking weight, quality/budget/safety rule and the keyset cursor are unchanged; the area condition is part of the same `WHERE`, so pages stay stable.
- Search telemetry records only which kind of scope applied (`locationSource`), never coordinates or codes.

The client decides whether its position is fresh enough to send; the server cannot judge it.

- Integration on isolated PostgreSQL/PostGIS Testcontainers: new `search-administrative.int.spec.ts` (5 tests: commune and whole-province scope with server labels; position wins without intersection; unscoped `none`; wrong parent, unknown code, partial area and unpublished dataset; area scope across cursor pages without duplicates). `search.int.spec.ts` 24 still passes.

Not run: DEV deploy, device acceptance, the rest of the integration suite.

## Rollback

Revert the application; nothing is persisted. Clients that send the new parameters to an older server get unscoped results and no `meta.location`, which the consumer must treat as unknown scope.
