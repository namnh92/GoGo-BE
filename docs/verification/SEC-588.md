## Protection boundary

**Guaranteed by structure.** From the API, no incoming request body, cookie, `env`/IP address, or request header outside `accept`, `accept-language`, `content-length`, `content-type`, `user-agent` and `x-request-id` reaches Sentry. The worker sends nothing to Sentry. The only attached extra is `request_id`. The request log records only method, URL, host and remote address for a request.

**Guaranteed by pattern, and tested.** In every remaining string or object — URL, query string, exception values and their causes, breadcrumbs, logged error fields — these are replaced with `[redacted]`: values of coordinate-named keys and parameters (`lat`, `lng`, `lon`, `latitude`, `longitude`, `…Lat`, `…_lat`); whole values under `coordinates`, `bbox`, `bounds`, `viewport`, `latlng`, `ll`, `geom`, `geometry`, `point`; decimal pairs with at least three decimals on both sides separated by `,` or `%2C`, including right after an encoded `@`; Google Maps `!3d…!4d…`; WKT and EWKT geometries; Drizzle `params:` lists; PostgreSQL `Failing row contains (…)` and `Key (…)=(…)` values.

**Not guaranteed.** A single unnamed decimal in free text; pairs coarser than three decimals (about 110 m); positions under other names or in other encodings (encoded polylines, geohashes, bare EWKB hex); data attached through a Sentry API call or integration added without updating this boundary (`sentry-usage.spec.ts` fails first for SDK calls); whether DEV sets `SENTRY_DSN`.

**Keeping it.** Route every Sentry call through `apps/api/src/sentry.ts`. `sentry-usage.spec.ts` fails when a file other than `sentry.ts`, `main.ts` and the exception filter imports the SDK, or when those files make any other call. `sentry-options.spec.ts` fails if request bodies, PII, local variables or tracing are switched on.

## Validation

`apps/api/src/sentry.spec.ts` runs a real Sentry client with `requestDataIntegration`, `linkedErrorsIntegration` and an in-memory transport. It feeds a search URL with `bounds`, `lat` and `lng`; a `referer` carrying an encoded Maps URL; a cookie; a captured body with a Maps link, a GeoJSON geometry, a nested `location`, a CSV row and room origin fields; a console breadcrumb with a coordinate pair and nested `latitude`/`longitude`; an outgoing breadcrumb with a `viewport` query; a failed insert whose Drizzle message binds EWKT and whose cause echoes `POINT(…)` with a `Failing row` detail; and an import error quoting a CSV row, a duplicate `Key (lat, lng)` and a GeoJSON body. The serialized envelope contains none of the four coordinate strings and still carries method, the redacted URL and query, `user-agent`, `x-request-id`, `request_id`, exception types, the SQL text with placeholders, the stack, and breadcrumb URL and status.

Mutation check: with the three hooks replaced by identity functions, the same spec fails on the first coordinate assertion. `sentry-options.spec.ts`, `sentry-usage.spec.ts`, `telemetry-redaction.spec.ts` and `logger.spec.ts` cover the structural settings, the call-site guard, each pattern with false-positive guards (versions, money, UUIDs, timestamps, SQL, coarse pairs, durations), and the request log.

Not run: a real Sentry project, DEV.

## Rollback

Revert. Telemetry returns to sending positions from request bodies, headers and the unnamed shapes above; nothing is stored or migrated.
