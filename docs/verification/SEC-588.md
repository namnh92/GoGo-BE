# SEC-588 — no exact position in Sentry events or request logs

Refs #588. This change owns coordinate redaction for both telemetry sinks. It supersedes the request-log change in GoGo-BE#585 (commit `f5099b2`), which is dropped from that PR; merge this one first.

## What carried a position

Verified in the installed `@sentry/node` / `@sentry/node-core` / `@sentry/core` 10.71.0 sources on develop `da6a89e`, and in a captured payload (`apps/api/src/sentry.spec.ts`).

| Event field                                | Where the SDK takes it from                                                                                                                                                          | Position in it                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `request.url`                              | `requestDataIntegration`; `httpRequestToRequestData` builds the absolute URL with its query; `include.url` is always true                                                            | `GET /v1/search?lat=&lng=` (develop), `GET /v1/administrative/locate?lat=&lng=` (#585) |
| `request.query_string`                     | the raw text after `?`; included unless `dataCollection.urlQueryParams === false`, and the default deny list only matches credential-like names                                      | same routes                                                                            |
| `request.headers`                          | included by default, minus credential-like names                                                                                                                                     | a `referer` URL can carry coordinates                                                  |
| `request.data`                             | `httpServerIntegration` defaults to `maxRequestBodySize: 'medium'` and captures up to 10 kB of every incoming body; `include.data` is always true; `httpBodies: []` does not gate it | `originLat`/`originLng`, `lat`/`lng` in JSON bodies                                    |
| `breadcrumbs[].data['http.query']`         | outgoing `http` and `fetch` breadcrumbs strip the query from `data.url` but keep it here                                                                                             | any outgoing call with coordinates in its query                                        |
| `breadcrumbs[].message` / `data.arguments` | `consoleIntegration`                                                                                                                                                                 | anything passed to `console.*`                                                         |
| `exception.values[].value`                 | the error message; Drizzle's `DrizzleQueryError` is `Failed query: …\nparams: …`                                                                                                     | a failed search query binds `lng`, `lat`                                               |

Not carrying one: `transaction` (tracing is off; only `httpServerSpansIntegration` names it, from the route), stack-frame variables (`localVariablesIntegration` needs `includeLocalVariables`, which is unset), `extra` (only `request_id`), tags (none set).

The request log had the same two paths: `req.url` with its query, and Pino's standard error serializer copying a `DrizzleQueryError`'s message and enumerable `params` array.

## Change

- `libs/observability/src/telemetry-redaction.ts` redacts by name: the value of a coordinate-named key or query parameter (`lat`, `lng`, `lon`, `latitude`, `longitude`, camelCase `…Lat`/`…Lng`, snake_case `…_lat`/`…_lng`) in URLs, bare query strings, free text, JSON text, objects and `[name, value]` pairs. A Drizzle `params:` list has no names, so the list is dropped whole. `sdkProcessingMetadata` is passed through untouched because the SDK strips it before sending and still uses it.
- `apps/api/src/sentry.ts` is the only Sentry initialisation: `beforeSend`, `beforeSendTransaction` and `beforeBreadcrumb` run every payload through that redaction. `main.ts` uses it.
- Request log: `redactUrl` replaces `lat`/`lng`/`latitude`/`longitude` query values with `[redacted]`, and a new `err` serializer applies the same redaction and replaces a `params` property.

## Kept

Method, path, every other query parameter, other header and body values, `request_id`, exception type, stack and query text (placeholders only), breadcrumb URL, method and status.

GitHub Actions (billing-blocked), a real Sentry project (whether DEV sets `SENTRY_DSN` is unverified), DEV.

## Rollback

Revert this change. Telemetry returns to sending positions; nothing is stored.
