# BE-BFF-019 — helpful reactions and the most helpful three

Refs #571. Stacked on BE-BFF-018 (#570, PR #587). Policy: ADR-0026, where every decision is a PROPOSAL awaiting product confirmation. Contract alpha.33. Migration 0066.

Behaviour: `PUT`/`DELETE /reviews/{id}/reactions/helpful` add and remove one `helpful` mark per account per review, idempotently, and answer `{ reviewId, helpfulCount, reactedByMe }`. Signed-in accounts only (guest `403 USER_ONLY`, anonymous `401`), never on your own review (`403 OWN_REVIEW`); anything not published on a readable place is `404 REVIEW_NOT_FOUND`. Rate limit `reviews.react` per actor, 120/hour with a burst of 30/minute. `GET /places/{id}/reviews?order=helpful` ranks `helpfulCount desc, createdAt desc, id desc` and equals `latest` when nothing has a mark; `order` defaults to `latest` and each review now carries `helpfulCount`. `GET /me/review-reactions?placeId=` lists only the caller's own marks. Counts are derived with `count(*)`, never stored. Export lists the reactions a person gave; account deletion removes them.

Migration 0066 creates `review_reactions` only (PK `review_id, user_id, type`, CHECK `type = helpful`, index on `user_id`), journal `when` above the reserved 0063–0065. Rollback: application rollback leaves the table unused; rehearsal-only down `DROP TABLE review_reactions;`.

Validation: 1,604 unit tests pass (8 new). Integration on isolated PostgreSQL/PostGIS containers, one file at a time: `review-reactions` 12 tests (double submit sequential and simultaneous, idempotent remove, own review, guest and anonymous, unpublished and hidden-place reviews, helpful ranking, tie-break on newest then id, fallback to latest, unknown order, emergency hide and re-publish, no reactor identity in public, export and deletion); `place-reviews` 12 tests (BE-BFF-018 behaviour with the new fields); `migration-upgrade` 9 tests; `libs/database` schema 11 tests. One early run of `review-reactions` saw a pg-pool "timeout exceeded when trying to connect" 500 on one of three simultaneous marks while lint and typecheck ran on the same machine; three later isolated runs passed 12/12 and no double count occurred in any run. Lint, format, typecheck, `api:check`, `api:routes`, `check:boundaries` and `api:version` (alpha.32 → alpha.33) pass.

Not run: DEV deploy, device acceptance, unrelated integration suites. Deploy after BE-BFF-018 and before Mobile APP-060 (#219). Keep the issue open until product confirms ADR-0026 and acceptance passes.
