## Implementation and choices

- Pure newest-text classifier; code-reviewed Vietnamese/English JSON lexicons;
  `PLACE_QA_CONFIG_VERSION=s3-v1`. S2 whole-boundary alternative readings and
  truth table remain authoritative, with a 32-reading cap that clarifies rather
  than truncates. CMS amenity/suitability labels and synonyms use a separate QA-only read/cache and never extend the serialized intent taxonomy. All fact eligibility remains S2's policy; no new verification
  or freshness rule. Dataset area identity is projected in the same statement
  for branch confirmation, without changing recommendation/card policy.
- The hook runs inside the original first-text guard, before recommendation
  history/episode work. Default-off flag; control handling/filtering survive
  disabling. Send/admission/funding and the credit bound version are unchanged.
- Name-only text is an equality probe: persist the route before lookup, restore
  the ordinary path only after a complete non-match and before any frame. A
  failure/cancel retains the safe QA marker. Losing the turn fences fallback.
- Reference-only S1 groups now include a closed internal `notice` kind (localized
  template key, no IDs), for neutral/not-found/narrow outcomes. No wire field or
  answer-token grammar changed. Branch options activate the IDs already in
  contract 10.1; generated documentation is refreshed; version pins unchanged.
- Pending v1 supports choice/confirm/narrow/referent. Candidate max three, plus
  “none”; source/config/semantic version/expiry checks; one retry; 30-minute
  lifetime retained across continuation. A bound option selects directly;
  typed ordinals/canonical names ask for confirmation. Typed `xác nhận <name>` /
  `đúng là <name>` (English `confirm <name>`) confirms the latest confirm state.
  “None” narrows, never concludes not-found. New named questions replace pending
  state; current-area refinement reruns the original complete name search.
- Legacy district yields mandatory confirmation and current dataset area labels.
  No district-to-successor inference. Explicit unresolved names never use context
  as fallback. Resolved single-place context is supported.
- **Compare choice:** recognize comparison grammar and return neutral unsupported
  QA, never recommendation/model fallback. Full compare, previous-card referents,
  `place_topic` chips/client binding and aliases remain S4/S5 pending.
- Durable `questionMessageId` is generated by `insertTurn`, never by the client.
  Route is persisted before QA lookups; terminal updates merge trace; orphan
  finalization preserves it. Recommendation history and episode-source SQL
  exclude QA pairs before the window limit, independently of the flag.
- Trace stores only closed semantics, references and timestamps. Telemetry labels
  have no text/name/id. QA records zero calls and known zero model cost; orphan
  zero-cost handling requires a durable QA marker **and** no attempt rows.
  Provider attempts with unknown cost retain existing conservative treatment.

### Root causes and changes

- **Prefix clause overlap:** `lastQuestionClause` scanned from the start of the
  message, including inside an already recognized prefix. For “Giờ mở cửa của
  Quán Sao Lạ”, it selected “mở cửa của Quán Sao Lạ” as a suffix, leaving no
  usable name between the prefix and suffix. The same mechanism affected the
  parking/suitability prefixes, unknown-name cases, typo prefixes and legacy
  district case. Accented and folded inputs both failed; this was not a
  no-diacritic normalization or context-ID defect. Start suffix scanning after
  the complete prefix. Preserve S2's whole-name alternate readings and area
  spans. Authority: shape rev3 §§3.1, 4.1, 4.3, 4.4.
- **Nested clause head:** scanning forward one character at a time let “đậu xe”
  replace “có chỗ đậu xe”, moving “có chỗ” into the fuzzy name. Advance over a
  complete topic head from the existing lexicon; later independent question
  heads still take precedence, including “Cafe Đánh Giá giá bao nhiêu?”. This
  explains why `parking-12` previously appeared to pass with only one card: it
  was searching the wrong, longer span. No resolver threshold changed.
- **Typo oracle:** the real fixture contains `Quán Sao Lạ`, `Quán Không Giá` and
  `quán X`. The latter two share the `quan` trigram run and qualify under S2's
  provisional weak threshold for the correctly extracted `Quán Sao Lạa`.
  Shape rev3 §4.3 row 5 requires the top three fuzzy candidates, with no margin
  rule and no automatic answer. Correct the exact candidate set; assert the
  highest-scoring Lantern card first and compare the complete set without
  fixing the order of the UUID-tied remaining candidates. The candidate set
  still requires a Docker PASS-after run; no SQL execution is claimed here.
- **Resume oracle:** `unclear` intentionally produces deterministic
  `turn_relation` clarification, with no search/cards/proposal or Haiku compose.
  Correct the Haiku count to zero, retain byte-identical complete adapter request
  comparison, and require the same rendered reply plus the `turn_relation`
  follow-up in both clean and QA-interposed conversations. Authority: shape
  rev3 §3.2 (line 81), retaining existing recommendation behavior; implementation
  evidence: orchestrator's `relation === 'unclear'` route and composable guard.
- **Index hypothesis ruled out for this harness:** setup already calls
  `placeNameKeyIndex(f.db)`. That helper executes the actual
  `scripts/ops/index-place-name-key.sql` statements in autocommit, including its
  readiness/shape assertion. Migration 0102 remains verify-only. No second index
  path, migration edit or product read-error fallback was introduced. The logged
  `clarify_referent` cases are reproduced before resolver invocation.
